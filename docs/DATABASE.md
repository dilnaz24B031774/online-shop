# База данных SaudaGo

PostgreSQL 16, 25 таблиц. Схема создаётся миграциями Django (`python manage.py migrate`).

- **ER-диаграмма:** [erd.png](erd.png) (для печати и слайдов), [erd.svg](erd.svg) (можно увеличивать без потери качества), исходник [erd.mmd](erd.mmd)
- **Все колонки, ключи и правила:** [db_tables.md](db_tables.md)
- **Обновить после изменения моделей:** `python manage.py db_docs`, потом `mmdc -i docs/erd.mmd -o docs/erd.png -s 2 -b white`

Диаграмма и справочник создаются из моделей автоматически, поэтому всегда совпадают с настоящей базой.

## Группы таблиц

| Группа | Таблицы | Для чего |
|---|---|---|
| Пользователи | `users`, `addresses`, `cities`, `login_security_state`, `login_challenges` | аккаунт, роли (customer / manager / admin), город и сроки доставки, адреса, защита входа |
| Каталог | `categories`, `products`, `product_images` | товары на трёх языках, остатки, галерея фото |
| Покупатель | `cart_items`, `favorites`, `reviews`, `review_photos`, `stock_subscriptions`, `notifications` | корзина, избранное, отзывы с фото, «Сообщить о поступлении», уведомления |
| Заказ | `orders`, `order_items`, `promo_codes`, `promo_redemptions` | заказ, его товары по цене на момент покупки, промокоды |
| Оплата | `payments`, `saved_cards`, `qr_payments`, `refunds` | оплата, сохранённые карты (токен), QR-оплата с телефона, возвраты |
| Поддержка и безопасность | `complaints`, `telegram_accounts`, `telegram_challenges` | книга жалоб с ответом магазина, восстановление пароля через Telegram |

## Главные связи

- `users` 1 — N `orders` 1 — N `order_items` N — 1 `products`
- `orders` 1 — 1 `payments` 1 — 0..1 `qr_payments`
- `order_items` 1 — N `refunds`: можно вернуть часть товаров из позиции
- `promo_codes` 1 — N `promo_redemptions` N — 1 `users`: кто и в каком заказе использовал код
- `products` 1 — N `product_images`: главное фото в `products.image_url`, остальные в галерее

## Правила прямо в базе (CHECK и UNIQUE)

Даже если в коде будет ошибка, база не сохранит неправильные данные:

| Правило | Где | Что защищает |
|---|---|---|
| UNIQUE `lower(username)`, UNIQUE `lower(email)` | users | `Aigerim` и `aigerim` — один аккаунт; то же для e-mail |
| UNIQUE (phone) WHERE phone <> '', `phone ~ '^\+[0-9]{7,15}$'` | users | один номер — один аккаунт, номер в одном формате (+77011111111) |
| `price > 0`, `stock_quantity >= 0` | products | нет бесплатных товаров и отрицательного склада |
| `rating BETWEEN 1 AND 5`, отзыв привязан к оплаченной покупке (`order_item`) | reviews | отзыв только после покупки, один на покупку |
| UNIQUE (user) WHERE is_default | addresses | только один адрес «по умолчанию» |
| `refunded_quantity <= quantity` | order_items | нельзя вернуть больше, чем куплено |
| `refunded_amount <= amount` | payments | нельзя вернуть больше денег, чем оплачено |
| `last4 ~ '^[0-9]{4}$'`, карта только у метода card | payments, saved_cards | хранятся только 4 цифры, полного номера и CVC нет |
| UNIQUE (user, promo) | promo_redemptions | промокод один раз на покупателя |
| `used_count <= max_uses` | promo_codes | лимит использований кода |
| UNIQUE (user, product) WHERE notified_at IS NULL | stock_subscriptions | одна активная подписка на товар |
| UNIQUE (product, url) | product_images | одно фото не добавляется дважды |
| `position < 3`, UNIQUE (review, position) | review_photos | не больше 3 фото в отзыве |
| `delivery_days_max >= delivery_days_min` | cities | правильный срок доставки |
| `expires_at > created_at`, оплачено → есть устройство | qr_payments | QR-код с правильным сроком |

## Транзакции

- **Оформление заказа** (`services.place_order`) выполняется одной транзакцией. Строки товаров блокируются (`SELECT … FOR UPDATE`), остаток проверяется, создаются заказ, позиции и оплата, склад списывается, корзина очищается. Если ошибка на любом шаге, откатывается всё. Два покупателя не смогут купить последний товар одновременно.
- **Отмена, возврат и просроченная оплата** тоже выполняются в транзакции: товар возвращается на склад, промокод снова становится доступен, деньги возвращаются пропорционально скидке.
- **QR-оплата** блокирует строку оплаты, поэтому один QR нельзя оплатить дважды.

## Безопасность данных

- Пароли хранятся только в виде хэша (PBKDF2).
- Номер карты и CVC никогда не сохраняются: только тип, 4 последние цифры и токен `tok_…`.
- QR-ссылка содержит случайный одноразовый токен, а не номер заказа.
- Демо-заказы помечены `orders.is_demo`, поэтому «Топ» и отчёты считают только реальные покупки.

## Резервные копии

`python manage.py backup_db` сохраняет всю базу через pg_dump в папку `backups/` (если pg_dump не найден, сохраняет данные в JSON). Хранятся последние 10 копий. `python manage.py restore_db ИМЯ --yes` восстанавливает базу, но сначала сохраняет текущее состояние. Администратор может сделать и скачать копию в панели: «Резервные копии».

## Каталог

`python manage.py load_catalog` добавляет товары, категории «Кухня» и «Продукты» и галереи фото. Команду можно запускать много раз: она ничего не удаляет и не меняет цены и остатки существующих товаров. Источник данных и фото: DummyJSON (бесплатные тестовые данные для магазинов). Русские и казахские тексты — наш перевод.
